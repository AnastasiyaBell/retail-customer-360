# Dashboard data contract

Generated by `scripts/run_pipeline.py`. All CSVs below are local and Git-ignored. `data/processed/portfolio/dashboard_manifest.json` records actual columns and row counts. Snapshot day is 711 for the initial dataset, not today's calendar date. Existing audit and EDA files remain separate.

## Private relational package: `data/processed/portfolio/bi_private/`

| File | Grain and key | Use |
|---|---|---|
| `household_snapshot.csv` | One `household_key` at `cutoff_day` | Latest RFM, cluster, active-180-day risk and contribution scenario. Not a historical segment table. |
| `sales_lines.csv` | Eligible source product line, not a unique basket-product key | Additive `sales_value`; distinct basket/household counts support category and time filters. |
| `basket_fact.csv` | `basket_id` after household/day validation | Basket sales; avoid connecting it directly to line facts. |
| `dim_day.csv` | One relative `day`, mapped to `source_week` | Integer day/week filters; no fabricated dates. |
| `dim_product.csv` | One `product_id` | Product, department, category, brand. |
| `dim_campaigns.csv` | One `campaign` | Source campaign type and validity bounds. |
| `campaign_contacts.csv` | Household/campaign pair | Received-campaign record, observed redemption count, end-of-campaign coverage flag. `start_day` is campaign validity start, not verified contact timestamp. |

Household-level `crm_candidates.csv`, `crm_targets.csv` and model snapshots are in the parent `portfolio/` folder, not the public package. Contacts and redemption counts do not estimate campaign uplift. TypeA individual coupon selections are unknown. The private package is for local workbook development, not a Tableau Public upload.

## Aggregate package: `data/processed/portfolio/bi_public/`

Aggregates contain no household identifiers or customer target lists. This reduces disclosure but does not itself establish redistribution rights. Review original dataset terms before uploading any extract. Tableau Public exposes workbook data; no file has been published by this project.

| File | Grain | Correct aggregation / filter scope |
|---|---|---|
| `weekly_sales.csv` | `source_week`, latest `segment` | Sum sales and baskets across weeks/segments; AOV = SUM(sales_value)/SUM(paid_baskets). Household counts are distinct within each week only: never sum them into a period unique-household total. `observed_days` repeats across segments: use MAX per week. |
| `category_sales.csv` | Category, latest segment, entire observation horizon | Sum sales across categories/segments. Household counts may be summed across disjoint segments for one category, not across categories. No week field: date filters cannot be applied. |
| `segment_summary.csv` | Latest segment at snapshot day | Sum households, 180-day monetary/frequency and scenario contribution. Mean recency must be weighted by households when combining segments. No historical date filter. |
| `cohort_retention.csv` | First-observed cohort and period age | One cell per cohort/age. Active households / original cohort size only if observation_complete. Never sum rates or cohort_size across ages. Cohorts are not acquisition cohorts. |
| `period_retention.csv` | Completed 30-source-day transition | Retained / previous active within one period. Do not confuse with full-history repeat buyers. |
| `risk_distribution.csv` | Latest segment, probability band | Sum household counts. Only active-180-day scored population; excludes unscored inactive households. |
| `model_metrics.csv` | Model, validation/test split | Display each metric directly, not summed. Select one split. |
| `calibration_bins.csv` | Probability bin, selected model's frozen test | Mean risk vs observed no-purchase fraction, with rows as support. Bin rows contain repeated household snapshots. |
| `cluster_summary.csv` | Selected latest K-Means cluster | Original-scale profiles; no sum of medians. Cluster IDs have no business order. |
| `crm_scenarios.csv` | One margin/uplift scenario ID at configured fixed budget/offer | Select exactly one scenario for cards. Rows are alternative plans, not additive results. No arbitrary budget slider; regenerate for a different budget. |
| `crm_selected_segments.csv` | Segment among targets in the default configured scenario | Default-scenario breakdown only. Must not respond as if recalculated for other sensitivity scenarios. |

## Segment and period semantics

Latest RFM membership is attached retrospectively to historical sales. A graph showing past sales by latest segment does not show historical segment changes. RFM uses 180 days; overview sales can cover the full source horizon. Display those different windows in page subtitles.

For public workbooks, period and category filters have **page-local scopes** because the aggregate category file has no temporal grain. A single global category/date/segment filter across every table would create misleading results. Use the private line-level package if fully combined category/time distinct-count analysis is required; rebuild source-window segments through Python rather than pretending a dashboard date slider recomputes RFM.

## Expected baseline checks

Full-horizon eligible retailer sales: USD 8,057,443.80; paid baskets: 275,539; households: 2,500; AOV: USD 29.24248037. The snapshot segment household total must equal 2,500. Cohort period-zero retention is 100% for completed cohorts. Incomplete cells stay blank. Only scored households appear in risk charts. Campaign and CRM outputs are not measured incremental profit.
